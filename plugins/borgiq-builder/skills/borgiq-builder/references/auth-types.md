# Authentication Types Reference

Authentication types for HttpRequestActor. Use via `connection.auth` or configure directly.

## Auth Type Enum

| Type | Value | Description |
|------|-------|-------------|
| AWS | `awsKeyBased` | AWS Signature V4 authentication |
| OAuth1 | `oauth1` | OAuth 1.0 authentication |
| OAuth2 | `oauth2` | OAuth 2.0 authentication |
| Bearer | `bearer` | Bearer token authentication |
| Basic | `basic` | Basic username/password authentication |
| API Key | `apiKey` | API key in header or query params |
| Custom | `custom` | Custom headers, query params, or body |
| MCP OAuth | `mcpOauth` | OAuth 2.1 to a remote MCP server, discovered and registered automatically |
| None | `none` | No authentication |

## TypeScript Schema Definition

```typescript
import { z } from 'zod';

export enum AuthType {
  AWS = 'awsKeyBased',
  OAUTH1 = 'oauth1',
  OAUTH2 = 'oauth2',
  BEARER = 'bearer',
  BASIC = 'basic',
  API_KEY = 'apiKey',
  CUSTOM = 'custom',
  MCP_OAUTH = 'mcpOauth',
  NONE = 'none',
}

/** Authenticate http requests using AWS Signature V4 */
const AWSV4AuthDataSchema = z.object({
  accessKey: z.string()
    .describe('Your AWS access key ID from your AWS Console'),
  secretKey: z.string()
    .describe('Your AWS secret access key from your AWS Console'),
  sessionToken: z.string().nullish()
    .describe('Your session token from your AWS Console'),
  signQuery: z.boolean().nullish()
    .describe('Sign the query instead of adding an Authorization header, defaults to false'),
  awsRegion: z.string().nullish()
    .describe('The region of the AWS service, defaults to us-east-1'),
  serviceName: z.string().nullish()
    .describe('The AWS service you are accessing'),
});

/** Authenticate http requests using API Key */
const APIKeyDataSchema = z.object({
  key: z.string()
    .describe('The key to add to the header or query params'),
  value: z.string()
    .describe('The value to add to the header or query params'),
  addToHeader: z.boolean()
    .describe('Add the key and value to the header instead of query params'),
});

/** Authenticate http requests using Bearer Token */
const BearerDataSchema = z.object({
  token: z.string()
    .describe('The bearer token to add to the Authorization header'),
});

/** Authenticate http requests using OAuth1 */
const OAuth1DataSchema = z.object({
  consumerKey: z.string()
    .describe('A value used to identify a consumer with the service provider'),
  consumerSecret: z.string()
    .describe('A value used by the consumer to establish ownership of the key'),
  token: z.string().nullish()
    .describe('A value used by the consumer permission to access the user\'s data'),
  tokenSecret: z.string().nullish()
    .describe('A value used by the consumer to establish ownership of a given token'),
  signatureMethod: z.string().nullish()
    .describe('The method the API uses to authenticate requests'),
  callback: z.string().nullish()
    .describe('URL service provider will redirect to following user authorization'),
  verifier: z.string().nullish()
    .describe('Verification code from service provider after user auth'),
  timestamp: z.string().nullish(),
  nonce: z.string().nullish()
    .describe('A random string generated by the client'),
  version: z.string().nullish()
    .describe('The version of the OAuth authentication protocol (1.0)'),
  realm: z.string().nullish(),
  includeBodyHash: z.boolean().nullish()
    .describe('Hash for integrity check with request bodies'),
  addEmptyParamsToSign: z.boolean().nullish()
    .describe('Add empty parameters to the signature'),
  disableHeaderEncoding: z.boolean().nullish()
    .describe('Disable header encoding'),
  addParamsToHeader: z.boolean().nullish()
    .describe('Add parameters to the header instead of the query string'),
});

/** Authenticate http requests using OAuth2 */
const OAuth2DataSchema = z.object({
  token: z.string()
    .describe('The oauth 2 token generated'),
  prefix: z.string()
    .describe('The prefix to add to the Authorization header'),
  addToHeader: z.boolean()
    .describe('Add the token to the header instead of query params'),
});

/** Authenticate http requests using Basic Auth */
const BasicAuthDataSchema = z.object({
  userName: z.string()
    .describe('The username to add to the Authorization header'),
  password: z.string()
    .describe('The password to add to the Authorization header'),
});

/** Authenticate http requests using Custom Auth */
const CustomAuthDataSchema = z.object({
  headers: z.record(z.string(), z.union([z.string(), z.number(), z.boolean()])).optional()
    .describe('The headers to add to the request. Overrides duplicate header keys.'),
  queryParams: z.record(z.string(), z.unknown()).optional()
    .describe('The query params to add to the request. Overrides duplicate query param keys.'),
  body: z.record(z.string(), z.unknown()).optional()
    .describe('The body keys to add to the request. Overrides duplicate body keys.'),
});

/** Combined auth schema - discriminated union by type */
const AuthDataSchema = z.discriminatedUnion('type', [
  z.object({ type: z.literal(AuthType.AWS), values: AWSV4AuthDataSchema }),
  z.object({ type: z.literal(AuthType.API_KEY), values: APIKeyDataSchema }),
  z.object({ type: z.literal(AuthType.BEARER), values: BearerDataSchema }),
  z.object({ type: z.literal(AuthType.OAUTH1), values: OAuth1DataSchema }),
  z.object({ type: z.literal(AuthType.OAUTH2), values: OAuth2DataSchema }),
  z.object({ type: z.literal(AuthType.BASIC), values: BasicAuthDataSchema }),
  z.object({ type: z.literal(AuthType.CUSTOM), values: CustomAuthDataSchema }),
]);
```

## Auth Type Details

### Bearer Token

Most common for REST APIs. Adds `Authorization: Bearer <token>` header.

```yaml
# Using connection (recommended)
options:
  auth: ${{ connection.auth }}
connection:
  key: my-api-connection

# Using credentials directly
options:
  auth:
    type: bearer
    values:
      token: ${{ credentials.apiToken }}
```

### Basic Auth

Username and password authentication.

```yaml
options:
  auth:
    type: basic
    values:
      userName: ${{ credentials.username }}
      password: ${{ credentials.password }}
```

### API Key

Add API key to header or query params.

```yaml
# In header
options:
  auth:
    type: apiKey
    values:
      key: X-API-Key
      value: ${{ credentials.apiKey }}
      addToHeader: true

# In query params
options:
  auth:
    type: apiKey
    values:
      key: api_key
      value: ${{ credentials.apiKey }}
      addToHeader: false
```

### OAuth2

For OAuth2 authenticated connections. Usually managed by workspace connections.

```yaml
# Typically used via connection
options:
  auth: ${{ connection.auth }}
connection:
  key: my-gmail-connection
  type: gmail
```

Auth structure when using OAuth2:
```yaml
auth:
  type: oauth2
  values:
    token: <access_token>
    prefix: Bearer
    addToHeader: true
```

### MCP OAuth

For connecting to a remote MCP server that uses OAuth 2.1. Unlike `oauth2`, you do not supply a
client ID or secret: BorgIQ discovers the server's authorization server and registers itself
dynamically (RFC 7591), so the only thing you provide is the MCP server URL.

Use this when an MCP server expects each client to register itself — Linear and Notion both work
this way. If the provider issued you a client ID and secret up front, use `oauth2` instead.

```yaml
# Created as a workspace connection; the MCP server URL is the only required input.
connection:
  key: my-linear-mcp
  type: mcp-server
```

The connection resolves to a bearer token at request time, so an actor consumes it exactly like any
other bearer credential:

```yaml
auth:
  type: bearer
  values:
    token: <access_token>
```

Notes:

- The server must advertise a dynamic client registration endpoint. If it does not, BorgIQ cannot
  register a client — use the generic OAuth 2.0 connection type with a pre-registered client.
- Tokens refresh automatically; re-authorization is only needed if you change the server URL or scope.

### AWS Signature V4

For AWS services authentication.

```yaml
options:
  auth:
    type: awsKeyBased
    values:
      accessKey: ${{ credentials.aws.accessKey }}
      secretKey: ${{ credentials.aws.secretKey }}
      sessionToken: ${{ credentials.aws.sessionToken }}  # optional
      awsRegion: us-east-1
      serviceName: execute-api
```

### OAuth1

For legacy OAuth 1.0 APIs.

```yaml
options:
  auth:
    type: oauth1
    values:
      consumerKey: ${{ credentials.oauth.consumerKey }}
      consumerSecret: ${{ credentials.oauth.consumerSecret }}
      token: ${{ credentials.oauth.token }}
      tokenSecret: ${{ credentials.oauth.tokenSecret }}
      signatureMethod: HMAC-SHA1
```

### Custom Auth

For APIs with non-standard authentication requirements.

```yaml
options:
  auth:
    type: custom
    values:
      headers:
        X-Custom-Auth: ${{ credentials.customToken }}
        X-Client-ID: ${{ credentials.clientId }}
      queryParams:
        signature: ${{ credentials.signature }}
```

## Best Practices

1. **Use connections** - Prefer `connection.auth` over hardcoded auth for OAuth services
2. **Use credentials** - Never hardcode credential values; use `${{ credentials.* }}`
3. **Typed connections** - Use `type: gmail` for one allowed connection type, or `type: [github-oauth2, github-pat]` when several registered connection types are acceptable
4. **Validate auth** - Check that required auth is present in error handling
